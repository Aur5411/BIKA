## 新增与改动

**章节目录**

- 修复 100 话以上只加载出二三十话：并发翻页 + 整体超时 + 5 分钟缓存 + 不轻信服务端空页
- 服务端截断时按章节序号补出缺失的前置章节（占位标题形如「第 12 話」），可直接点开阅读
- 边拉边显示：第一个网络来回就铺出前 20 话，不再整屏转圈；失败仍整份报错，不展示残缺列表
- 新增按钮：回到顶部 / 回到底部 / 正序倒序（连同原下载共四个，同尺寸同配色），
  两个滚动按钮同一组显隐、动画不互相打断
- 顶部信息行写明状态：「共 160 话 · 最新话在前」，加载中显示「已加载 20 话 …」

**首页** 移除顶部「最近浏览漫画」（设置页未动）。

**分流 / 网络** 冷启动自动探测并切到最低延迟线路（API 与图片成对选取）；设置页测完延迟
自动应用最低延迟 IP；IP 分流增强（多 IP 边缘池、并发探测、失效黑名单、按 `/24` 归并、快照兜底）。

**图片加载** 补上缺失的图片磁盘缓存（Coil 不会自动创建），此前每次冷启动都要重下所有封面。
现在内存缓存 25%，磁盘缓存按可用空间 2% 自适应（64 MB ～ 2 GB）。

**图片加载速度**（本轮）

- **最快源自动选路**：竞速决出的最快域名会被记住，之后的每张图在进 Coil 链之前就
  改写到它，不再"每张图都先打一遍慢源"。源失效即忘掉重选，选路结果 10 分钟后过期重测
- **补请求头**：图片链路原来没有浏览器 UA / Referer，Cloudflare 前面的镜像
  （实测 `storage.tipatipa.xyz`）会对默认 OkHttp UA 直接 403；403 会被降级逻辑当成
  "主源失败"，于是每张图都要白跑一轮换域名竞速
- **竞速阈值 2.5s → 0.9s**：慢源不再被白等两秒半才去找更快的源
- **并发拉满**：图片同域名并发 16 → 32、全局 64 → 128，连接池与解码线程池跟着配齐；
  Coil 的取流/解码改用专用线程池，不再和下载、数据库抢同一个 `Dispatchers.IO`
- **预载拉大**：预载并发 5 → 12（原来小于窗口宽度，窗口根本喂不满），
  快读窗口 10 → 16、精读 3 → 6，基准预载默认 2 → 8，设置滑杆上限 16 → 24
- **候选源** 新增 `img.picacomic.com`；全部候选统一由 `ImageHosts` 维护

**图片加载速度**（第二轮：找根因）

第一轮把并发、预载都拉满了，但实测发现并发数换不来带宽——根因不在参数，在协议：

- **强制图片链路走 HTTP/1.1**：图片 CDN 支持 HTTP/2，OkHttp 默认优先 h2，于是所有图片
  被塞进**同一条 TCP 连接**多路复用，而这个 CDN 上的 h2 吞吐只有几十 KB/s。同一份文件、
  同样并发数实测：h2 单连接 44 ~ 115 KB/s，HTTP/1.1 多连接 1784 ~ 3007 KB/s，
  **差 20～60 倍**。h2 下再大的 `maxRequestsPerHost` 也换不成吞吐，必须钉死协议，
  上面那 32 并发才有意义
- **连接预热**：一次 TLS 握手实测 1.0～1.3 秒，连接复用时首字节才 400ms——"第一张图迟迟
  不出来"里有一大截是在做密钥协商。进入阅读会话时并发摊好几条连接放进池子里 idle 5 分钟
- **提前选路**：预热阶段顺带并发探一遍所有候选源，把最快的那个先记下来，第一张图就直接打它，
  不必再从慢主源起步、熬到竞速阈值才去找更快的源
- **可见页按画布采样解码**：`AsyncImagePainter` 在没设 `sizeResolver` 时会兜底成
  `SizeResolver.ORIGINAL`，2000×3000 的扫描页也被解成同尺寸 Bitmap（单张 20 MB 起），
  解码时间随像素线性增长。现在按画布约束采样，只砍掉超出屏幕的冗余像素

同一轮的验证过程里也排除了两条路：CDN 支持 Range，但**多线程分片拉一张图反而更慢**
（8 线程只有单线程的 0.89 倍，还偶发失败），所以没有走这条路；多条连接，h2 下不存在这个前提。

**读一会儿之后图片全部加载不出来**（第三轮：修限流)

图片跑快之后出现的新问题：长章节翻过二十来页，后面的图再也出不来。原因是服务端
对短时间内的图片请求做配额限制，超限回 429，而降级逻辑把 4xx **一律**当成"这个 path 上
就是没有"的永久性失败——于是每张图直接判死，既不换源也不重试，同时预载还在满并发继续拽图，
把配额烧得更干净。修法是把"被限流"当成一等公民处理：

- **429 / 503 不再判死**：交给外层 `ImageThrottleInterceptor` 等窗口过去再重试同一张图
- **全局节流闸门**（`ImageRateGovernor`）：在飞请求上限 16；吃到限流就指数退避
  （1.2s → 2.4s … 上限 30s），一次成功即清零自愈
- **限流期间不再打 source 竞速**：配额通常按 IP/账号计，此刻并发打其余候选域名只会更快烧光
- **预载在限流期直接放弃**：用户此刻看不见它，它的边际收益是负的，让出配额给可见页
- 传输层超时/5xx 的可见页请求补一次退避重试；预载不重试，避免为"下一页更快"多付请求量
- 取流/解码的并行闸门改用 `Dispatchers.IO.limitedParallelism`：原先的自建固定线程池下，
  竞速子协程与等待中的父协程排在同一批线程上，有线程饥饿风险

**榜单** 加 10 分钟缓存，从漫画返回榜单不再重新转圈。

**阅读器** 上下章改由「章节序号 + 服务端自报总数」判定，目录被截断或尚未加载完时
「下一章」不再被误置灰；首章无上一章、末章无下一章。

**其它** 修复下载完成后进度不置 100；修复阅读进度防抖写入会把进度写退；详情页标签改惰性列表；
补齐多个模块缺失的测试依赖，430 项单元测试全部通过。
