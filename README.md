## 新增与改动功能

### 一、章节目录（本次改动最大的部分）

**1. 目录不再加载不全**

原来 100 话以上的漫画只加载出二三十话，缺的恰好是最老的几十话。原因是章节接口按
「最新话在前」分页，翻到中途一停，被截掉的正是开头那一段。现在：

- **并发翻页**：从"一页一页串行等"改成按批并发，120 话从 7 个网络来回压到 3 个；
- **整体超时**：整份目录 15 秒拿不到就明确失败并给出重试，不会一直转圈；
- **5 分钟缓存**：从详情页进阅读器再返回，不再重拉整本；
- **不轻信"空页"**：服务端偶发把中间某页返回成空、或把越界页重复上一页，现在会结合
  服务端自报的章节总数判断"其实还没拉完"，继续往后探；
- **服务端截断时自动补齐**：若服务端只给到 90 话却自称 160 话，会按章节序号把缺失的
  前置章节补出来（占位标题形如「第 12 話」）。阅读器定位章节靠的是序号，所以
  补出来的条目**可以直接点开阅读**。

**2. 边拉边显示**

第一个网络来回回来就把前 20 话铺出来，剩余章节继续加载并在列表末尾提示
「正在加载剩余章节…」，不再整屏转圈干等。中途失败仍会整份切到错误页，
**绝不展示一个"看起来齐了其实少几十话"的列表**。

**3. 目录页新增三个按钮**

右下角悬浮按钮自上而下：**回到顶部 → 回到底部 → 正序/倒序 → 下载**（四个按钮同尺寸同配色）。

- **正序 / 倒序**：一键切换，只重排已到手的列表，不产生新请求；切换后自动回到顶部。
- **回到顶部 / 回到底部**：离开列表顶端后两个按钮**一起出现、一起消失**
  （装在同一组动画里，不会互相打断）。
- 顶部信息行写明当前状态，例如「共 160 话 · 最新话在前」，加载中显示
  「已加载 20 话 · 第 1 话在前」。

### 二、首页

- **移除顶部的「最近浏览漫画」区块**（设置页内容保持原样未动）。

### 三、分流与网络

- **冷启动自动选源**：启动时并发探测各分流线路的握手延迟，自动切到延迟最低的一条，
  API 与图片域名成对选取，避免只更新了一边、留下半套配置。
- **IP 分流增强**：多 IP 边缘池、并发探测、失效 IP 黑名单、按 `/24` 归并优选、
  探测结果落盘快照兜底、一次注入多个 IP 而不是单个。
- **设置页自动应用最低延迟**：进设置页会自动测量所有候选 IP 的延迟，测完**直接**把
  API 与图片各自切到延迟最低的那一个（原先是必须手动点「应用最低延迟」，实际没人会点）。
  图片 IP 会被应用到所有 `*.picacomic.com` 图片域名，所以这一项直接决定封面 / 章节图的快慢。

### 四、图片加载

- **补上了缺失的图片磁盘缓存**（这是封面加载慢的根因）。Coil 不会自动创建磁盘缓存，
  而原代码没有显式配置，导致**每次冷启动、每次进新页面所有封面都要重新下载**，
  阅读器里那些磁盘缓存策略也因此全部失效。现在配置为：

  - 内存缓存：应用可用内存的 20%
  - 磁盘缓存：`cacheDir/image_cache`，按可用空间 2% 自适应，下限 64 MB、上限 512 MB

  效果：首次浏览仍要下载，但**退出重进 App 再翻同一批封面基本瞬开**；
  设置页里的「图片缓存大小」也会从 0 B 变成一个真实数字。

### 五、榜单

- **加了 10 分钟缓存**：从漫画返回榜单不再重新转圈加载；用户主动刷新会绕过缓存。

### 六、其它修复

- 修复**下载任务完成后进度不置 100**（带租约的那条更新语句漏写 `progress` 字段）。
- 修复**阅读进度写入的两个缺陷**：防抖分支缺少闸门二次检查，切章后迟到的旧页码仍会写库；
  立即写入路径没有顶掉防抖窗口里未到期的旧值，会把进度写退回去。
- 详情页标签改为**惰性列表**，减少首屏组合量与无谓的图片加载。
- 补齐了多个模块缺失的测试依赖（此前 CI 只跑构建、从不跑单元测试），
  现在 **416 项单元测试全部通过**。

## 自己编译

```bash
./gradlew :app:assembleRelease -PminifyWithR8=false
```

仓库根目录另附 `build.bat` / `build.sh` 便捷脚本，已内置 JDK 与 Android SDK 路径。

产物：`app/build/outputs/apk/release/BIKA_v1.11.23_*.apk`

> **打包注意**：请**不要**在构建沙箱隔离下打包。沙箱会拦截打包过程中的文件操作，
> 产出条目残缺的 APK（缺 `AndroidManifest.xml`、`resources.arsc`、整个 `res/`），
> 而且因为过程是确定性的，重复构建会产出 SHA256 完全相同的坏包，
> 只看 `BUILD SUCCESSFUL` 根本发现不了。交付前建议校验 APK 内部条目数
> （本项目为 476 条）与关键文件是否存在。
